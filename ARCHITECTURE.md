# 🏗️ Архитектура проекта

## Обзор системы

Canvas Deadline Assistant Bot - это асинхронный Telegram-бот для отслеживания дедлайнов заданий в Canvas LMS.

│  │         Handlers (handlers.py)                        │ │
│  │  • /start - Приветствие                             │ │

## Структура файлов

### 📋 Основные файлы

#### `main.py` - Точка входа приложения
- Инициализирует Bot и Dispatcher
- Настраивает APScheduler для фоновых задач
- Запускает polling Telegram Bot API
- Управляет жизненным циклом приложения

**Ключевые функции:**
- `main()` - Главная функция запуска
- `scheduler_init()` - Инициализация планировщика
- `check_deadlines()` - Фоновая задача проверки дедлайнов

#### `handlers.py` - Обработчики команд бота
Содержит все команды, которые может выполнять бот:

- `@router.message(Command("start"))` → cmd_start()
  - Отправляет приветственное сообщение
  
- `@router.message(Command("help"))` → cmd_help()
  - Отправляет справку по использованию
  
- `@router.message(Command("set_link"))` → cmd_set_link()
  - Валидирует и сохраняет ссылку на iCal-фид
  
- `@router.message(Command("check"))` → cmd_check()
  - Показывает ближайшие дедлайны пользователя
  
- `@router.message(Command("status"))` → cmd_status()
  - Показывает статус подписки

#### `database.py` - Работа с базой данных
Асинхронное взаимодействие с SQLite через aiosqlite.

**Структура таблицы `users`:**
```sql
CREATE TABLE users (
    user_id INTEGER PRIMARY KEY,      -- Telegram ID пользователя
    ical_url TEXT NOT NULL,           -- URL на iCal-фид Canvas
    created_at TIMESTAMP DEFAULT...,  -- Время добавления
    updated_at TIMESTAMP DEFAULT...   -- Время последнего обновления
)
```

**Основные функции:**
- `init_db()` - Инициализация БД и создание таблиц
- `save_user_link(user_id, ical_url)` - Сохранение/обновление ссылки
- `get_user_link(user_id)` - Получение ссылки пользователя
- `get_all_users()` - Получение всех пользователей (для фоновой задачи)
- `delete_user(user_id)` - Удаление пользователя
- `user_exists(user_id)` - Проверка наличия пользователя

#### `parser.py` - Парсинг iCal-фидов
Обработка календарных данных из Canvas LMS.

**Основные функции:**
- `validate_ical_url(url)` - Валидация формата URL
  - Проверяет, что URL начинается с http/https
  - Проверяет наличие расширения .ics
  
- `fetch_ical_events(ical_url)` - Скачивание и парсинг событий
  - Делает HTTP запрос к URL
  - Парсит iCal формат
  - Возвращает стуктурированные события
  
- `get_deadline_events(ical_url)` - Получение событий за 3 дня
  - Получает события, дедлайн которых за 71-72 часа
  - Это обеспечивает ровно одно уведомление за 3 дня
  
- `get_next_deadlines(ical_url)` - Получение ближайших дедлайнов
  - Возвращает до 5 ближайших дедлайнов
  - Используется для команды /check

#### `config.py` - Конфигурация приложения
Централизованное хранилище всех настроек.

**Основные параметры:**
- `BOT_TOKEN` - Токен бота
- `DATABASE_PATH` - Путь к БД
- `HTTP_REQUEST_TIMEOUT` - Timeout для запросов
- `DEADLINE_CHECK_HOURS_START/END` - Диапазон для проверки (71-72 часа)
- `CHECK_INTERVAL_HOURS` - Интервал проверки (1 час)
- `MAX_NEXT_DEADLINES` - Макс. количество дедлайнов для /check
- `LOG_FILE`, `LOG_FORMAT`, `LOG_LEVEL` - Параметры логирования

#### `logger_setup.py` - Настройка логирования
Единая конфигурация логирования для всего приложения.

Логирует в:
- Файл `bot.log` (для истории)
- Консоль (для оперативного контроля)

## 🔄 Алгоритм работы

### 1. Запуск бота
1. Загрузка конфигурации из `.env`
2. Инициализация БД (создание таблицы users если нужно)
3. Подключение к Telegram Bot API
4. Запуск APScheduler
5. Начало polling сообщений

### 2. Команда /set_link [url]
1. Пользователь отправляет команду с URL
2. Валидитор проверяет формат URL
3. Если валидна → сохранение в БД
4. Отправка подтверждения пользователю

### 3. Команда /check
1. Получение сохраненной ссылки пользователя из БД
2. Скачивание iCal-фида
3. Парсинг событий
4. Получение 5 ближайших дедлайнов
5. Отправка форматированного списка

### 4. Фоновая задача (каждый час)
1. APScheduler вызывает `check_deadlines()`
2. Получение всех пользователей из БД
3. Для каждого пользователя:
   - Скачивание его iCal-фида
   - Поиск событий с дедлайном за 71-72 часа
   - Если найдены → отправка уведомления в Telegram
4. Логирование результатов

### 5. Обработка ошибок
- Если URL недоступен → логирование, продолжение работы
- Если парсинг не удался → логирование, продолжение
- Если отправка сообщения не удалась → логирование, продолжение

Бот никогда не падает из-за ошибок в календарях пользователей!

## 🧵 Асинхронность

Почти все операции асинхронные:

- **HTTP запросы** - httpx.AsyncClient
- **Работа с БД** - aiosqlite
- **Планировщик** - AsyncIOScheduler
- **Обработчики** - async def
- **Фоновые задачи** - asyncio

Это позволяет боту обслуживать много пользователей одновременно без блокировок.

## 📊 Поток данных

```
Пользователь
    ↓
    GET /set_link https://canvas.../calen.ics
    ↓
handlers.py (cmd_set_link)
    ↓
    Валидация → parser.validate_ical_url()
    ↓
    Сохранение → database.save_user_link()
    ↓
    Ответ пользователю
    
────────────────────────────────────

main.py (check_deadlines каждый час)
    ↓
    Получение пользователей → database.get_all_users()
    ↓
    Для каждого:
        ↓
        Скачивание фида → parser.fetch_ical_events()
        ↓
        Поиск дедлайнов → parser.get_deadline_events()
        ↓
        Если есть → bot.send_message()
        ↓
        Логирование → logger
```

## 🔐 Безопасность

- **Токен хранится в .env** (добавлен в .gitignore)
- **Данные пользователей локальны** (SQLite на диске)
- **Нет передачи чувствительных данных на сторонние сервисы**
- **URL маскируется в /status** (показывается только первые 50 символов)

## 📈 Масштабируемость

Текущая архитектура подходит для:
- До **1000+ пользователей** (зависит от Canvas)
- **Любого числа дедлайнов** (нет лимитов на парсинг)
- **Добавления новых команд** (просто добавить в handlers.py)

Для масштабирования на большие объемы:
1. Переместить БД на PostgreSQL + async драйвер
2. Использовать Redis для кэширования
3. Разделить фоновые задачи между несколькими инстанциями
